# 会话审计模块的变异测试账

`pnpm mutate:audit`（收缩到 `src/audit` + 两个测试文件）：

```
350 个位点   杀掉 269~270   幸存 80~81   超时 0   退出码 3（基线）

（同一份代码连跑两次会差 1~2 个——变异器的结果缓存不是严格幂等的，
所以这个数字只能当区间看。）
```

**这不是零幸存。** 这份文档记的是「哪些能证等价、哪些还欠着」。

## 为什么不能拿全 src 的 `pnpm mutate` 当这条线

全 src 是 828 个位点 × 每次跑完整套件（13s），小时级。收缩到审计模块后一轮 ~90 秒，
才有迭代的余地。命令见 `package.json` 的 `mutate:audit`。

## 能逐条证等价的：`?? -> ||`（25 个位点全部）

判定标准只有一条：**左值可能是 falsy-but-defined 吗？** 只有 `0` 和 `""` 会让
`??` 与 `||` 分道。逐个看：

| 位置                                                 | 左值                                          | 结论                                                           |
| ---------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------- |
| `claims.ts:58` `text[i + 1] ?? ""`                   | `string \| undefined`，字符不可能是 `""`      | 等价                                                           |
| `claims.ts:133` `inner.split(/\s+/)[0] ?? ""`        | `split` 至少返回一个元素，永远不是 undefined  | 等价                                                           |
| `claims.ts:143,144,147,148,149,150` `m.index ?? 0`   | `matchAll` 的 `index` 一定是 number           | 等价                                                           |
| `claims.ts:162` `raw.split("/").pop() ?? ""`         | 非空数组的 `pop` 恒有值                       | 等价                                                           |
| `claims.ts:226,228` `lastCmd ?? prevSentenceLastCmd` | `lastCmd` 是 `number \| null`，**0 是 falsy** | **不等价**；由「完成词绑到跑过但失败」「跨句兜底」两条用例守住 |
| `normalize-claude.ts:76,112` `x ?? {}`               | 对象或 undefined                              | 等价                                                           |
| `normalize-claude.ts:140` `textOf(...) ?? ""`        | `textOf` 空内容返回 undefined，从不返回 `""`  | 等价                                                           |
| `normalize-codex.ts:89,116,117,121,150,161,181,206`  | `string \| undefined` 或对象                  | 等价                                                           |
| `verdict.ts:183` `opts.maxReceipts ?? DEFAULT_MAX`   | **0 是 falsy**                                | **不等价**；由 `maxReceipts: 0` 用例守住                       |
| `verdict.ts:186` `report ?? …`                       | **`""` 是 falsy**                             | **不等价**；由「空报告 ≠ 没给报告」用例守住                    |
| `verdict.ts:188` `opts.claims ?? …`                  | 对象                                          | 等价                                                           |

即：`??` 这一类里 22 个位点可证等价，3 个不等价的都已各有一条用例钉住。

## 行为指纹（这一轮的主力）

手写用例只能钉住想得到的情况，而死不掉的那批恰好落在「想不到但可达」的输入上。
所以补了两份**确定性语料 + 行为指纹**：

- `test/session-audit-fuzz.test.ts`：60 条固定种子生成的报告 × 固定事件集，
  逐条比 `claims` / 判词 / `mismatch` / `notes` 的 FNV 指纹；
- `test/session-audit-normalize-fuzz.test.ts`：codex 24 种、claude 24 种字段组合，
  逐份比归一化后的事件数组。

语料由固定种子的 LCG 生成，跑多少次都一样；行为**故意**变了才重新生成指纹。
这两份把幸存者从 95 压到 89；再加「边界行为表」（空命令、点开头隐藏文件、
侧链、未配对 tool_result、`Exit code N` 只认开头）压到 **84**。

## 没能逐条证的

其余约 60 个幸存者分布在 `&& -> ||`、`0 -> 1`、`=== -> !==`、`>= -> >` 这几类。
它们**不是**整类都能证等价——同一类里既有被杀掉的位点、也有幸存的位点，
按类下结论会把「已经被测试咬住的」和「真没覆盖的」混在一起。

要收口，得逐位点做：把变异体插进源码、跑测试、看它为什么不红。`mutator` 的
`.metrics/mutate/*.edn` 里存的是内部表示的字节偏移，和源码行号对不上（试过把
注释、类型擦除几种归一化都对不齐），所以这一步目前只能手工做。
